# Recipe: Product Revision

**When to suggest this:** the user is revising an already-shipped or already-planned product, so the starting point is an existing state with prior decisions to respect.

## Lens sequence

1. current-state inventory (surface existing assumptions and constraints before changing anything)
2. problem-framing
3. pr-faq
4. pre-mortem (optional)
5. mvp-scoping
6. success-metrics (before/after comparison against the current baseline)

Steps marked `(optional)` may be skipped when the revision is low-risk. Jumping back to problem-framing after the pre-mortem surfaces a false assumption is expected.

This is a suggested order, never forced. It is not a slash command; the meta-skill offers it in one line and proceeds on the user's own sequence if they prefer.
