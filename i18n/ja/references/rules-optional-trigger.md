# 🔵 Optional ステップ トリガールール

> Optional ステップのトリガー条件と Phase 判定ポイントフォーマットの正式な情報源。Full / Revision / Custom モードのルールファイルから読み込まれます。

このファイルは Optional ステップのトリガー条件を集中管理し、各モードのルールファイルが重複定義しなくて済むようにします。

---

## 1. Core（コア）と Optional（オプション）の定義

- **Core（コア）**：常に実行。ユーザーの明示的な上書き指示なしでスキップ不可。
- **Optional（オプション）**：少なくとも 1 つのトリガー条件が満たされた場合のみ実行。ユーザーはいつでも強制追加または強制スキップが可能。

---

## 2. Persona-Journey バンドルルール（グローバル）

**Journey Map は Persona の自然な延長です：Persona は Who を定義し、Journey Map は Who が経験する旅程を描きます。Persona ステップが完了したら、Journey Map はデフォルトで含まれ、状況が本当にマッピングするには単純すぎる場合のみスキップされます。**

> ⚠️ このルールは「0-to-1 には Journey Map は不要」という以前の誤った想定を修正するものです。実際は逆で、Teresa Torres（Continuous Discovery）、Indi Young（Mental Models）、Amazon Working Backwards プロセスはいずれも、新しい体験設計の形を決定づけるため、0-to-1 段階でも Journey Map を不可欠なものとして扱います。関連する変数は**ユーザーの Job が複数ステージにまたがるかどうか**であり、プロダクトが既に存在するかどうかではありません。

### スキップ条件（デフォルト ON；以下のいずれか 1 つを満たした場合のみスキップ）

1. **単一インタラクションポイント** — Job が単一の API 呼び出し、単一のボタン、純粋なバックエンドサービス、または純粋な設定ツールで解決される（複数ステージのフローが存在しない）
2. **フローが 1〜2 ステップしかない** — ユーザーフロー全体が短すぎて、Journey Map が意味のあるステージ遷移のないリストに退化してしまう
3. **ユーザーが明示的にスキップを要求** — 例：「Journey Map をスキップ」「skip Journey Map」「我不需要 Journey Map」

### スキップ時の挙動

サイレントにスキップせず、判断結果をユーザーに提示します：

> 「Persona が完了しました。現在のコンテキスト（[単一インタラクションポイント / フローが N ステップのみ]）に基づき、Journey Map をスキップします。「add journey」と返信すればいつでも追加可能です。」

### トリガー時の挙動（デフォルト）

Journey Map ステップに入る前に、**なぜ**必要なのかを引用した簡潔な評価ノートを提示します：

> 「Persona が完了しました。Job が [N] ステージ（[ステージ A → ステージ B → ...]）にまたがるため、User Journey Map に進みます。不要であれば「-S3」と返信してスキップできます。」

## 5. Phase 判定ポイント 出力フォーマット

**Optional ステップを含む各 Phase に入る前に、AI はどの Core/Optional ステップを実行するか、その理由を列挙する Phase 判定ポイントブロックを必ず出力しなければなりません。**

### 必須フォーマット

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🔀 Phase [N] ステップ判定

✅ Core（必ず実行）：S[a], S[b]
🔵 Optional 評価：
  • S[x] [フレームワーク名]（デフォルト ON）：[実行 / スキップ] — [理由]
  • S[y] [フレームワーク名]（デフォルト OFF）：[トリガー / スキップ] — [理由]

→ この Phase では [N] ステップを実行します
（"+S[x]" と返信して強制追加、"-S[y]" で強制スキップ、または続行）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

デフォルト ON のステップ（例：S3 Journey Map）の場合、条件が成立していれば **実行**、スキップ条件が成立した場合は **スキップ** を使用します。
デフォルト OFF のステップ（例：S6 Positioning、S11 PMF/GTM）の場合、条件が満たされていれば **トリガー**、それ以外は **スキップ** を使用します。

### 表示タイミング

- 少なくとも 1 つの Optional ステップを含む各 Phase の冒頭で 1 回表示
- Core ステップのみの Phase では判定ポイント不要（直接進行）
- 表示後、ユーザーの返答を待つ。上書き以外の返答（「ok」「続行」、または実質的なコンテンツなど）は「AI の判定を受け入れる」を意味する

### ユーザーの上書きコマンド

| ユーザー入力 | 挙動 |
|------------|----------|
| `+S[x]` または「S[x] を追加」 | スキップされた Optional ステップを強制追加 |
| `-S[y]` または「S[y] をスキップ」 | トリガーされた Optional ステップを強制スキップ |
| 実質的なコンテンツ / 「続行」 / Enter | AI の評価を受け入れて進行 |

## 6. Custom Mode — Persona-Journey 条件付き挿入

Custom Mode のプリセット（Lean / Standard / Comprehensive）は固定のステップ順序を持ちますが、Persona ステップを含むプリセットには Persona-Journey バンドルルールが引き続き適用されます。

| プリセット | デフォルト挙動 | Persona ステップ後の挙動 |
|--------|------------------|----------------------------|
| **Lean** | Persona ステップなし | 該当なし |
| **Standard** | 8 固定ステップ、S1 = Persona | S1 の後、AI はセクション 2 の Persona-Journey 評価を実行します。スキップ条件が成立**しない**場合、AI は能動的に Journey Map を **S1.5 として挿入（9 ステップ実行となる）** し、ユーザーは `-journey` と返信して元に戻すことができます。スキップ条件が成立した場合は、サイレントにスキップして最終出力で開示します（セクション 7）。 |
| **Comprehensive** | 11 固定ステップ、S2 = Persona、S3 = Journey Map（既に含まれている） | AI は簡潔な「スキップ可能」ノートを提示できます：「Journey Map はデフォルトで含まれています。状況がマッピングするには単純すぎる場合は `-S3` と返信してください。」それ以外は通常通り進行します。 |

これにより、状況が本当にシンプルな場合に Lean/Standard ユーザーが中断されることを防ぎつつ、Journey Map から*恩恵を受ける*ユーザーがそれをサイレントに拒否されないことを保証します。

---

## 7. 最終出力での開示

モードが完了した際、最終のプロダクトスペックサマリーには、スキップされた Optional ステップを必ず列挙し、それらをワンコマンドで追加できるパスを提示しなければなりません。例：

> 「今回スキップされた Optional ステップ：S6（Positioning）、S11（PMF/GTM）。「add S6」または「add S11」と返信すれば補完できます。」
