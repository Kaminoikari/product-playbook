# 품질 리뷰 규칙

> 각 단계 후 로드.

## 프로토콜

각 단계 출력 후:
1. 각 체크리스트 항목을 ✅ 또는 ❌로 마크. 각 ❌는 명시: 갭, 하위 영향, 개선 방향.
2. **≥1 ❌ 필수** (Hard Gate). ⚠️로 대체 불가. "가장 약한 부분" 부록 우회 금지. ❌는 실질적 내용 갭이어야 하며, 형식/문구 아님. 모두 ✅로 느껴지면 → 기준 낮춰 재검토. 모든 산출물에는 가장 약한 측면이 있음.
3. 형식: `📝 품질 자체 점검:` 이어서 `- ✅/❌ 항목 → 갭 / 영향 / 개선`.

자체 점검의 자체 점검: ❌ 없음 → 2단계 재실행.

## 프레임워크별 체크리스트

**Persona**: 1) 인구통계가 아닌 용도/동기 기반, 2) MECE, 3) 핵심 vs 보조 TA 명확, 4) 페인포인트가 실제 관찰/추론, 5) "현재 대처법 + 이유"가 워크어라운드 식별 가능할 만큼 구체적.

**JTBD**: 1) 구체적 맥락 ("언제든"이 아님), 2) 단일 핵심 작업, 3) 기능적 + 감정적 + 사회적 모두 존재, 4) 솔루션 평가에 사용 가능, 5) "현재 방법 + 갭" 진술, 6) 5-Why Q5가 감정/정체성/두려움에 도달.

**Positioning (April Dunford)**: 1) 사용자 관점의 경쟁 대안, 2) 경쟁사가 따라올 수 없는 고유 속성, 3) 제품 언어가 아닌 사용자 언어의 가치, 4) 이 사람들을 찾을 수 있을 만큼 구체적인 타깃 시장, 5) 5개 요소 논리적 일관성.

**HMW**: 1) 명확한 제약, 2) 넓은 솔루션 공간, 3) JTBD/페인에 매핑, 4) 팀이 아이디어 시작 가능.

**PR-FAQ**: 1) 사용자 관점 헤드라인 ("사용자가 이제 X를 할 수 있게 됨"), 2) 첫 문단이 10초 내 "왜 이것이 중요한지" 전달, 3) 실제 시나리오의 페인, 4) 솔루션이 사용자 감정으로 시작, 5) 인용문이 사람답게 들림, 6) FAQ에 기존 도구 대비 날카로운 질문.

**North Star**: 1) 사용자 가치 반영 (매출/DAU 아님), 2) 지속적 성장 가능, 3) 팀이 보고 무엇을 해야 할지 앎, 4) 조작 가능하면 가드레일, 5) B2B: 조직 수준 가치.

**Aha Moment**: 1) 구체적 추적 가능한 행동, 2) JTBD 기능적 작업과 연결, 3) 목표 시간 합리적 (B2C: 첫 사용; B2B: 트라이얼 기간), 4) 가속화하도록 온보딩 설계 가능.

**보안** (전체: `08-security-checklist.md`): 1) 인증 방식 명시적 선택, 2) ≥3개 보안 헤더 계획, 3) 템플릿이 아닌 맞춤 rate limit, 4) `.gitignore`가 모든 민감 파일 커버.

**문서 내보내기** (전체: `rules-export-document.md`): 1) HTML에 잔류 Markdown 구문 없음, 2) 테이블 행/열이 원본과 일치.
